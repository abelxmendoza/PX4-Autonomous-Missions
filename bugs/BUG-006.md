BUG-006

Scenario:
Running `vv_replay` (the offline requirement-verification CLI) against a
real, recent flight log that included a clean avoidance maneuver toward
a confirmed-clear LiDAR sector.

Requirement violated:
REQ-AVOID-SENSOR-01 (avoidance shall be backed by live sensor evidence)
— the checker for this requirement itself was wrong.

Symptom:
`vv_replay` flagged REQ-AVOID-SENSOR-01 as FAILED on a flight where the
vehicle steered toward a sector LiDAR had explicitly confirmed clear —
arguably the single *safest* avoidance decision it could make.

Expected behavior:
`lidar_sectors.py` publishes `-1.0` for a sector to mean "scanned, and
nothing detected" — a fresh, valid, safe reading, not missing data. The
requirement check should treat that as evidence the avoidance decision
was sensor-backed.

Actual behavior:
`check_req_avoid_sensor_01` treated any `-1.0` reading as *missing*
sensor evidence (as if the sensor hadn't reported at all), so a decision
to steer into a confirmed-clear sector was scored as having no sensor
backing — a false positive for the very check meant to confirm sensor
grounding.

Root cause:
Conflating two different meanings of `-1.0` in the sector-range channel:
"no reading available" and "reading available, range is effectively
infinite / nothing in range." `lidar_sectors.py` only ever emits the
second meaning, but the checker was written for the first.

Fix:
Updated `check_req_avoid_sensor_01` in `vv_harness.py` to treat `-1.0`
as valid evidence of a clear sector, not absent evidence.

Regression test added:
`test_flight_vv.py::test_sensor_backed_avoidance_passes_with_confirmed_clear_sector`
— asserts a flight trace with a `-1.0` (clear) sector reading passes
this requirement instead of failing it.

Commit: 604bcd0

Note: this bug is in the verification harness itself, not the flight
code — a reminder that the thing checking for bugs needs its own tests
and can have false positives just like any other software. Found by
actually running the checker against a real flight log rather than only
synthetic fixtures, which is why `vv-regression` in CI now replays real
committed flight logs on every push, not just hand-built test traces.
