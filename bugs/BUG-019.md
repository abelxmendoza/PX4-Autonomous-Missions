BUG-019

Scenario:
Fault injection (`config/fault_scenarios/sensor_faults.yaml`): the stereo-VO
stream freezes -- keeps arriving with fresh timestamps but repeats its last
velocity -- for 5 s mid-flight, in the offline fusion rig.

Requirement violated:
Fault-injection expectation for `frozen_sensor`: a stuck sensor is detected
(health drops or measurements are rejected) rather than silently trusted, with
bounded error growth.

Symptom:
Before the fix, same seed, same scenario:
- detected 5.4 s after the freeze began (health dropped only once the filter's
  own state had drifted far enough to start rejecting the stale value);
- peak horizontal error +11.04 m above the fault-free baseline (final error
  10.2 m, no absolute reference to pull it back);
- fusion reported healthy for the first 5 s of the freeze.

Root cause:
`PoseVelocityEKF.update_velocity` accepted any measurement that was consistent
with the filter's current velocity. A frozen sensor is consistent with a state
it is itself dragging along, so every repeat was accepted and kept "refreshing"
the health timer. Nothing compared a measurement to its predecessor.

Fix:
A bit-identical repeat of a measurement above 0.2 m/s is rejected as a stuck
sensor (`stuck_rejections`). The 0.2 m/s floor exists because VO reports exactly
0 at rest: across five recorded SITL flights (F, G, H, K, L; 2,239 VO rows)
about 60% of rows are exact repeats, all of them below 0.05 m/s, and none above
0.2 m/s -- so the rule had zero false positives on recorded data.
After: detected in 0.6 s, error growth +0.08 m, recovery 0 s.

Regression test added:
`test_bit_identical_repeat_of_a_moving_velocity_is_rejected_as_a_stuck_sensor`,
`test_repeated_zero_velocity_is_not_a_stuck_sensor` (`test_ekf_fusion.py`);
scenario `sensor_faults/8-frozen_sensor` (vo) in `test_fault_scenarios_shipped.py`.
Two older tests fed the filter identical vectors as a stand-in for "consistent
VO"; they now add the float noise real VO always has.

Limit of the evidence: the false-positive rate was checked on 5 SITL flights'
VO output, not on hardware, and the freeze itself is injected at the
measurement (the rig does not run feature tracking).
