BUG-003

Scenario:
Live SITL flight through the obstacle course using LiDAR-based reactive
avoidance, close to an obstacle.

Requirement violated:
No formal REQ-ID (predates most of the V&V harness's avoidance
requirements). Violates the practical expectation that an avoidance
target, once chosen, should be actionable rather than immediately
superseded.

Symptom:
Near close obstacles, `lidar_sectors`' published `obstacle_dir` label
flipped between front/left/right on nearly every scan (~every 50ms),
causing the mission to thrash between different avoidance targets
instead of committing to one maneuver.

Expected behavior:
The obstacle-direction label should reflect a stable read of which
sector is actually blocked, changing only when the geometry genuinely
changes — not flicker tick-to-tick on sensor noise near a boundary
between sectors.

Actual behavior:
`lidar_sectors` re-published a new label on essentially every scan
based on the single latest reading, with no debounce. Right at a
sector boundary or with any sensor jitter, this produced rapid
front/left/right/front label changes, and downstream avoidance logic
re-targeted on every change.

Root cause:
The sector-labeling logic used only the most recent scan with no
persistence requirement — a single noisy or borderline reading was
enough to flip the published label.

Fix:
Added a `confirm_ticks` debounce to `lidar_sectors.py`: a candidate
label must persist across several consecutive scans before it is
published, so a single noisy reading can no longer flip the active
avoidance direction.

Regression test added:
None at the time of this fix — `test_lidar_sectors.py` covers sector
banding, EMA smoothing, and range-threshold edge cases but has no test
of the `confirm_ticks` debounce itself. Verified live via repeated
headless SITL flight runs showing stable avoidance targeting instead of
thrashing. This is a real coverage gap worth closing with a dedicated
unit test.
