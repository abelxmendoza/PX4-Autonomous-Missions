BUG-005

Scenario:
Live SITL flight through a dense cluster of obstacles, using either the
climb or sidestep avoidance strategy (the affected branch was shared by
both).

Requirement violated:
No formal REQ-ID at the time; this predates REQ-CLEARANCE-01. Directly
the kind of failure REQ-CLEARANCE-01 ("no mapped-obstacle intersection")
now exists to catch.

Symptom:
In dense obstacle clusters, the vehicle produced PX4 attitude-failure
warnings and erratic position estimates — consistent with routing into
a second obstacle while attempting to avoid the first.

Expected behavior:
When the lateral-avoidance branch decides to sidestep toward one side,
it should first confirm that side is actually clear before committing
to it.

Actual behavior:
The left/right lateral-avoidance logic always sidestepped toward the
same predetermined side, with no check for whether that side was itself
blocked. In a dense cluster, "the escape side" could be occupied by a
second obstacle, and the vehicle drove toward it while nominally
"avoiding" the first one.

Root cause:
The lateral-avoidance branch had no visibility into the live LiDAR
minimum ranges for the side it was escaping toward — it picked a side
based on the geometry of the *original* obstacle only, never
re-checking against current sensor data for the chosen escape path.

Fix:
Subscribed the lateral-avoidance branch to `lidar_sector_mins` and, if
the chosen escape side is itself within the danger margin, climb
instead of sidestepping into it.

Regression test added:
None at the time of this fix — verified live via repeated headless
SITL runs in dense obstacle layouts, confirmed by the absence of
further attitude-failure/erratic-position telemetry. A unit test
driving `_apply_avoidance` with `_sensor_mins` showing the "preferred"
escape side blocked, asserting it climbs instead of sidestepping into
it, would close this gap.

Commit: bf8deed (bundled with BUG-003 and BUG-004). This same commit
also reverted the default `avoidance_strategy` to "climb" project-wide,
since "sidestep" was not yet proven safe as a default in dense layouts
at this point in the project.
