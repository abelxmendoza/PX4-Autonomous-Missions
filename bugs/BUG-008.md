BUG-008

Scenario:
Live SITL flight through a harder obstacle-course layout where two
obstacles (OB1/OB5) were deliberately made genuinely un-climbable, so
the climb-avoidance strategy's front-obstacle fallback had to actually
choose a lateral escape side.

Requirement violated:
REQ-CLEARANCE-01 (no mapped-obstacle intersection) — this is a real
collision, the exact class of failure that requirement exists to catch.

Symptom:
PX4 attitude-failure/tumble telemetry consistent with an actual
collision. Live position telemetry showed the vehicle driving directly
into an obstacle rather than avoiding it.

Expected behavior:
When the climb strategy's front-obstacle fallback finds its chosen
escape side is also blocked, it must not proceed through that side —
it should try the opposite side, and only hold position (letting the
existing stuck-in-avoidance watchdog land safely) if truly boxed in on
every side.

Actual behavior:
The fallback logic checked whether the escape side was blocked, logged
a warning saying so — and then drove into it anyway. The check existed
in the code but never actually changed the resulting setpoint.

Root cause:
The blocked-side check was wired to logging only, not to the target
selection. It observed the danger and reported it, but the value it
computed for "where to fly" didn't depend on the check's result.

Fix:
Made the fallback actually try the opposite side first when the
preferred escape side is blocked, and only hold position (rather than
pick a side at all) when every side is genuinely blocked — letting the
stuck-in-avoidance watchdog safely land instead of forcing a maneuver
into a wall.

Regression test added:
None at the time of this fix — verified live: repeated SITL runs
through the same hardened obstacle layout showed no more
attitude-failure/tumble telemetry, and a clean
stuck-in-avoidance-watchdog → FAILSAFE → land sequence instead. A unit
test asserting the boxed-in branch returns a hold target (not a target
inside the blocked side) when all sides report blocked in
`_sensor_mins` would close this gap.
