BUG-001

Scenario:
First SITL preflight arming attempt on the obstacle-course world.

Requirement violated:
N/A — no formal REQ-ID existed yet at this point in the project; this
predates the V&V harness. Violates the general precondition that PX4
must see all required sensors before OFFBOARD/mission logic can run at
all.

Symptom:
PX4 refused to arm. Console showed:

    Preflight Fail: barometer 0 missing
    Preflight Fail: Found 0 compass (required: 1)

Expected behavior:
The x500 vehicle model publishes barometer and magnetometer data, PX4's
preflight checks pass, and the vehicle can arm.

Actual behavior:
No barometer or magnetometer topics were ever published on uORB. PX4's
EKF2/commander preflight checks failed outright, blocking arming before
any mission code could run.

Root cause:
Gazebo Harmonic requires the `AirPressure` and `Magnetometer` system
plugins to be declared at `<world>` scope for those sensors to simulate
at all. The world SDF only declared the `Imu` and `NavSat` plugins —
the barometer and magnetometer plugins were simply missing.

Fix:
Added the two missing world-level plugins to `worlds/obstacle_world.sdf`:

    gz::sim::systems::AirPressure
    gz::sim::systems::Magnetometer

alongside the existing Imu and NavSat plugins.

Regression test added:
None — this is a Gazebo world-configuration fix, not something a Python
unit test can exercise. Verified by confirming PX4's preflight checks
passed and arming succeeded in a live SITL run.
