BUG-004

Scenario:
Live SITL flight using the "sidestep" avoidance strategy, after every
mapped (AABB) obstacle had already been bypassed once, with LiDAR still
reporting something ahead.

Requirement violated:
No formal REQ-ID at the time. Violates basic availability: a crash in
the control loop stops setpoint streaming entirely, which is worse than
any individual avoidance failure.

Symptom:
The node crashed with:

    ValueError: min() arg is an empty sequence

Expected behavior:
When live LiDAR detects an obstacle that isn't in the known AABB map
(or every mapped obstacle has already been marked bypassed), the
avoidance logic should fall back to a sensor-only sidestep instead of
failing.

Actual behavior:
The sidestep-target selection unconditionally called `min()` over the
list of "remaining, not-yet-bypassed" mapped obstacles to find the
nearest one — with no obstacles left in that list, `min()` raised on an
empty sequence, taking down the whole control loop.

Root cause:
The nearest-obstacle lookup assumed the remaining-obstacles list was
always non-empty, which stopped being true once every mapped obstacle
had been bypassed but LiDAR still had something in view (e.g. a return
that isn't part of the known map).

Fix:
Added a fallback: when the remaining-obstacles list is empty, sidestep
from the current position using live LiDAR bearing instead of
obstacle-map geometry, and clamp the resulting bypass target against
the geofence at creation time.

Regression test added:
None at the time of this fix — verified live via repeated headless
SITL runs no longer crashing in this configuration. A dedicated unit
test asserting `_apply_avoidance` degrades gracefully (rather than
raising) when `_bypassed_obstacles` covers every mapped obstacle would
close this gap.
